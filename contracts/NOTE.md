# Local Solidity slice: status and blockers

The three contracts are deployed on Base Sepolia/Reactive Lasna for a no-value testnet rehearsal. One manually labeled test vector has traversed the cross-chain callback and paused the vault. This is not an AI-generated or production safety result. A guarded manual deployment script is available in [`DEPLOYMENT.md`](DEPLOYMENT.md).

Provisional topology supplied for implementation: Base Sepolia source/destination (84532), Reactive Lasna for the Reactive contract (5318007), and the operator-approved Uniswap v3 USDC/WETH 0.3% source pool `0x46880b404CD35c165EDdefF7421019F8dD25F4Ad`. The full Blockscout pagination run returned 28,727 Swap logs, each verified against a successful RPC receipt and block header; independent proof that the explorer indexed every chain log remains open. A read-only preflight confirmed chain IDs, deployed code at the documented System/proxy and factory/pool addresses, token order, fee and factory lookup. Those checks alone did not prove integration; a separate manual callback test is documented below. No unverified project deployment addresses or credentials are embedded in contract configuration.

Current official docs list Base Sepolia (84532) and Reactive Lasna (5318007) as supported testnets and prohibit mixing testnet and mainnet roles: [origins/destinations](https://dev.reactive.network/origins-and-destinations#testnet-chains). The current Reactive System address shown in [Reactive contracts](https://dev.reactive.network/reactive-contracts) is `0x8888888888888888888888888888888888888888`; the Base Sepolia callback proxy listed in the same official chain table is `0x476F44b11F5C942c58f4c8E3d0300E5710743585`. `ReactiveRiskGuard` takes its System address as constructor configuration so isolated tests can inject a test-only double; deployment must read back both addresses against the current docs before use. Test doubles exist only in `test/`.

Deployment ordering for the cycle-free destination setup: deploy `ScoreRegistry` on Base Sepolia, deploy `ReactiveRiskGuard` on Lasna with the registry address, deploy the vault on Base Sepolia with the guard as its expected sender, then call the guard's owner-only `configureDestinationVault` exactly once. The destination cannot be changed after configuration.

The Reactive and vault `pay(uint256)` entry points are nonpayable provider billing hooks: they transfer the requested amount from their own prefunded native balance to the authorized service provider. Their payable receive/constructor paths are for funding. Official [economy](https://dev.reactive.network/economy) and [callback-contract](https://dev.reactive.network/callback-contracts) docs state the Reactive contract needs REACT (Lasna testnet: lREACT) and the callback destination needs destination-native gas (ETH on Base Sepolia). The manual test used 0.1 lREACT and 0.001 ETH reserves; after callback the remaining reserves were 0.0850857 lREACT and 0.000999285484 ETH, both with zero debt. Future fees and delivery vary with gas and network conditions. The vault's `deposit()` itself remains nonpayable and value-free.

The manual test vector used score `9000`, threshold `7714`, and test-only model/source markers. The research model's latest snapshot score was `3601`, below threshold; the manual test must not be described as AI inference. The callback receipt matched the expected `DepositsPaused` event and the authoritative vault state reads paused; `deposit()` reverted while paused. The vault holds no deposited assets; service reserves contain only testnet gas tokens for provider fees.

Remaining blockers include independent source-completeness evidence, an operationally useful model and fresh holdout (current precision 5%), authenticated model publication, a live score-to-React pipeline, and continuous monitoring/reconciliation. Run `neural-brake-preflight` before any further transaction. Do not enable automatic publication or market protection.
